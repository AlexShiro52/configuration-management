## Оформление репозитория

| Правила | Результат |
|---|---|
| С1-С5 | README.md, .gitignore, src, tests, run.sh и run.bat присутствуют |
| С6 | Пять коммитов этапов и отдельный коммит объединения кода |
| Г1-Г5 | В отслеживаемых файлах нет архивов, бинарных файлов и кэшей |
| Р1 | Каждый файл короче 1000 строк |
| Р2 | Python-строки не длиннее 80 символов |
| Р6 | Код не содержит строк длиннее 120 символов |
| Ф1 | Максимальная длина функции - 25 строк, лимит 40 |
| А1 | Максимум 4 аргумента с учетом self, лимит 7 |
| К1 | Функции документированы docstring |
| Ц1 | Максимальная сложность Radon - 10, лимит 10 |
| М1 | Тайм-ауты вынесены в TIMEOUT и RENDER_TIMEOUT |
| И1 | Имена PEP 8, проверка pycodestyle без замечаний |

Правила для других языков неприменимы. В тестах числовые значения
описывают ожидаемые результаты конкретных примеров.
Итог: 23 unittest-теста проходят; отчет - evidence/tests.txt.
Тесты не требуют интернета, D2 и сторонних Python-библиотек.

## Организационные пункты

- Локальный git-репозиторий с историей этапов подготовлен.
- Публикация в публичном git-сервисе выполняется отдельно: до появления
  публичного URL этот пункт нельзя считать закрытым. Команды есть в README.
- Очную защиту на семинаре проходит студент. Материал для подготовки:
  docs/defense.md.
- PNG и ZIP передаются отдельно, не добавляются в git по правилам Г1/Г2.

Ограничения модели последних версий и компактного обработчика маркеров
явно описаны в README и comparison.md; результаты сравнений не выдуманы.
