# Вариант 26: граф зависимостей Python

Практическая работа № 2 по дисциплине «Конфигурационное управление»,
ИКБО-18-25, РТУ МИРЭА, 2026/2027.

Программа получает зависимости Python-пакетов из PyPI JSON API, строит
граф рекурсивным DFS, определяет порядок загрузки и сохраняет D2 и PNG.
Стрелка `A -> B` означает: **A зависит от B**.

## Требования и быстрый запуск

- Python 3.10+. Сторонние Python-библиотеки не нужны; сборка не требуется.
- Только для PNG: команда `d2` в PATH.
- Интернет для PyPI; тестовые JSON работают офлайн.

Команды выполняются из каталога `variant26`:

```sh
python3 -m unittest discover -s tests -v
python3 -m src.main --package A --test --repository examples/diamond.json
```

Результат: `graph.d2` и `graph.png`. Без D2 доступны этапы 1-4:

```sh
python3 -m src.main --package A --test --repository examples/diamond.json --stage 4
```

В macOS/Linux доступен `./run.sh` с теми же аргументами.
В Windows используйте `run.bat` либо `py -3 -m src.main`.

### Установка D2

В macOS с Homebrew:

```sh
brew install d2
d2 --version
```

Для Windows и Linux: [официальная установка](https://d2lang.com/tour/install/),
[готовые сборки](https://github.com/d2lang/d2/releases).
Исполняемый файл должен быть доступен как `d2` в PATH.
Проверено с D2 0.9.0. D2 используется только для рисования;
зависимости программа получает самостоятельно через urllib.

## Настройки

| Опция | Назначение | По умолчанию |
|---|---|---|
| `--package` | Имя пакета; в тестовом режиме A-Z | Обязательна |
| `--repository` | Базовый URL JSON API или тестовый JSON | `https://pypi.org/pypi` |
| `--test` | Включить тестовый репозиторий | Выключено |
| `--output` | Имя PNG, каталог должен существовать | `graph.png` |
| `--stage` | Этап от 1 до 5 | `5` |
| `--help` | Справка | - |

`--test` является флагом: не нужно писать `--test true` или `--test false`.
URL указывает на базу PyPI-совместимого JSON API, а не `/simple`.
Запрос имеет вид `<repository>/<package>/json`.
Рядом с PNG сохраняется одноименный `.d2`.
Существующий PNG заменяется только после успешной генерации нового.
Коды завершения: 0 - успех, 1 - ошибка данных/сети/D2/цикл на этапе 4,
2 - ошибка параметров CLI.

## Демонстрация пяти этапов

```sh
python3 -m src.main --package requests --stage 1
python3 -m src.main --package requests --stage 2
python3 -m src.main --package requests --stage 3
python3 -m src.main --package requests --stage 4
python3 -m src.main --package requests --output requests.png
```

1. Все параметры в формате `ключ=значение`, проверка ошибок ввода.
2. Только прямые зависимости пакета.
3. Полный достижимый граф в JSON: рекурсивный DFS, включая циклы.
4. Порядок «зависимости раньше потребителей»; диагностика пути цикла.
5. Описание D2 и изображение PNG.

Выводы, помеченные «только для этого этапа», не появляются на этапе 5.
HTTP-запросы имеют тайм-аут 20 секунд; метаданные кэшируются в пределах
запуска. Рендеринг ограничен 120 секундами. Ошибки не скрываются.

### Тестовые графы

```json
{"A": ["B", "C"], "B": ["D"], "C": ["D"], "D": [], "Z": []}
```

Вершины объявляются явно, имена состоят из заглавных латинских букв.
Повторяющиеся ребра удаляются, неизвестные зависимости вызывают ошибку.
Обход начинается с `--package`; недостижимая вершина Z не попадет в граф.

```sh
python3 -m src.main --package A --test --repository examples/diamond.json --stage 3
python3 -m src.main --package A --test --repository examples/diamond.json --stage 4
python3 -m src.main --package A --test --repository examples/cycle.json --stage 3
python3 -m src.main --package A --test --repository examples/cycle.json --stage 4
```

Для ромба: `D -> B -> C -> A`. На цикле этап 3 завершается успешно,
а этап 4 сообщает: `Нет порядка загрузки: цикл A -> B -> C -> A`.
Этап 5 умеет рисовать циклы. Другие примеры: `chain.json`, `single.json`,
`self.json`. Реальные результаты запусков: `docs/evidence/demo.txt`.

### Визуализация трех реальных пакетов

```sh
python3 -m src.main --package requests --output requests.png
python3 -m src.main --package flask --output flask.png
python3 -m src.main --package httpx --output httpx.png
```

В `examples/` сохранены `requests.d2`, `flask.d2`, `httpx.d2`.
Повторная генерация по сохраненному описанию без интернета:

```sh
d2 examples/flask.d2 flask.png
```

PNG приложены отдельно от git-репозитория: по правилам задания бинарные
файлы в репозитории запрещены. Сравнение графов и порядка установки:
[docs/comparison.md](docs/comparison.md). Для трех примеров вершины и ребра
совпали с pipdeptree; различия допустимых порядков установки объяснены.

## Структура и описание всех функций

Весь основной код находится в `src/main.py`. Файл `src/__init__.py`
содержит только описание пакета для запуска через `python3 -m src.main`.
Тесты сохранены в отдельных файлах. Также доступен прямой запуск:

```sh
python3 src/main.py --package requests --stage 2
```

|---|---|---|
| Параметры CLI | `arguments` | Разбор CLI, ошибки параметров с кодом 2 |
| | `validate` | Проверка имени, тестового файла и режима |
| | `validate_url` | Проверка HTTP(S) URL |
| | `validate_output` | Проверка PNG и доступности каталога |
| PyPI | `normalize` | Нормализация имени PyPI |
| | `package_name` | Выделение имени и extras из Requires-Dist |
| | `metadata` | HTTP-запрос JSON с кэшем и тайм-аутом |
| | `dependencies` | Прямые зависимости с учетом условий |
| Маркеры условий | `environment` | Значения маркеров текущего Python и ОС |
| | `compare` | Сравнение строк и числовых версий |
| | `evaluate` | Вычисление разрешенных узлов AST без eval |
| | `enabled` | Проверка маркера для базовой установки и extras |
| Граф | `read_graph` | Чтение и валидация тестового JSON |
| | `build_graph` | Построение графа рекурсивным DFS |
| | `build_graph.visit` | Отметка вершины до рекурсии в соседей |
| | `load_order` | Порядок загрузки или диагностика цикла |
| | `load_order.visit` | Постпорядок DFS и множество активных вершин |
| Визуализация | `to_d2` | Описание вершин и ребер на D2 |
| | `render` | Запись D2, вызов d2, проверка и сохранение PNG |
| Запуск | `source` | Выбор тестового либо HTTP-источника |

| | `main` | Обработка ошибок и возврат кода завершения |

`tests/` содержит unittest-тесты, `examples/` - JSON и D2,
`docs/evidence/` - результаты сравнений. Методы тестов описаны docstring.

## Алгоритм и границы модели

DFS записывает вершину в словарь **до** рекурсивного обхода зависимостей.
Поэтому каждая вершина обходится один раз, а обратное ребро цикла
сохраняется без повторного обхода. Время O(V + E), память O(V + E).
Для порядка загрузки вершина добавляется **после** обхода зависимостей.
Множество активных вершин и текущий путь позволяют показать цикл.
Глубина рекурсии ограничена Python; превышение выдается как ошибка.

Анализируются **метаданные последних версий**, а не план установки pip.
Ограничения версий из Requires-Dist не разрешаются. В варианте 26 нет
параметра версии и требования реализовать полноценный решатель pip.
На других пакетах результат может отличаться от pip, который выбирает
совместимые версии и учитывает уже установленные пакеты.

Учитываются условия среды и extras в транзитивных требованиях.
Обычная установка не включает extras dev/test. Требования `p[x]`
сохраняются отдельными вершинами; CLI принимает корень без extras.
Поддерживаются ==, !=, <, <=, >, >=, in, not in, and/or и скобки.
Числовые версии сравниваются покомпонентно: 3.10 > 3.9.
Это компактный обработчик, не полная реализация PEP 440/508: ~= и ===
вызывают ошибку, суффиксы версий сравниваются как строки.
На трех демонстрационных пакетах эти ограничения результат не меняют.
Произвольный код из метаданных не выполняется: eval не используется.

## Проверки и сдача

```sh
python3 -m unittest discover -s tests -v
git log --oneline --reverse
git status --short
```

Каждый этап сохранен отдельным Conventional Commit. Объединение кода
в один файл сохранено следующим коммитом; история этапов не изменена.
Папка `.git`
включена в комплект: не удаляйте ее, иначе потеряется история этапов.
В git не включены PNG, архивы, окружения и кэши Python.

Создайте пустой репозиторий без README/.gitignore на выбранном сервисе,
затем из этой папки выполните:

```sh
git remote add origin URL_ВАШЕГО_РЕПОЗИТОРИЯ
git push -u origin main
```

Публикуйте содержимое `variant26`, а не весь архив с PNG.
Проверьте, что репозиторий открывается без авторизации.
